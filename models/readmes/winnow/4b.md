# Winnow E4B

- **License:** Apache-2.0
- **Original model:** [EldanRing/Winnow-E4B](https://huggingface.co/EldanRing/Winnow-E4B)
- **Base model:** google/gemma-4-E4B-it
- **Served modalities:** Text and image input; text output.

## Description

Winnow E4B is EldanRing's merged Gemma 4 E4B fine-tune for typed decisions,
chat, and image input. This registry entry serves chat and image input through
upstream llama.cpp `llama-server`. It does not expose Winnow's typed-decision
API: the existing Decider engine uses a different prompt and label readout.
The decision benchmarks shown on Ollaya do not validate this chat integration.

## Run

```bash
self serve winnow:4b
```

Use the [Text API](/api/text) at `/v1/chat/completions`. Image input uses
user-message `image_url` content parts; the current adapter accepts one image
per request. Audio and video are not exposed.

## Quantizations and Files

The default and only registered variant is `q8`, using the author's merged
`gguf/Winnow-E4B-Q8_0.gguf` (8,005,437,472 bytes) and matching F16 vision
projector `gguf/mmproj-Winnow-E4B.gguf` (990,372,672 bytes).
Both files are GGUF, pinned to revision
`ed891438b340bb60e2962e335fe100b2796c2124` with SHA-256 checks in the registry.
No separate base model, LoRA adapter, or speculative assistant is needed.

## Settings and Limits

Startup context is 8,192 tokens; the upstream Q8 runtime profile has tested
65,536 positions, including image tokens. Override with `--set context_size=65536`
when memory permits. Thinking is off by default. Model download size excludes
KV cache and runtime overhead.

The upstream fitted Q8 decision temperature of 1.2574172017327816 applies to
option-logit scoring, not chat sampling. Native typed decisions require a
separate Winnow-specific adapter. Runtime inference through `self` has not been
smoke-tested for this entry.
